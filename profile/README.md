# ln80

**An open-source toolkit for privacy and security engineering.**

ln80 builds libraries and tools that help developers and AI agents build more private and secure applications.

The focus is on practical building blocks for handling sensitive data, protecting information, and getting security right.

## Projects

### [privacy-engine](https://github.com/ln80/privacy-engine)

Privacy and data protection primitives for Go.

Field-level encryption, tokenization, subject-scoped keys, and cryptographic erasure.

### [struct-sensitive](https://github.com/ln80/struct-sensitive)

A simple way to work with sensitive fields in Go structs.

Identify, scan, mask, and redact fields using struct tags.

### [crypto-convoy](https://github.com/ln80/crypto-convoy)

An end-to-end encrypted team-storage protocol with a TypeScript implementation.

Client-side encryption, key management, and client-enforced access control.

## How we build

- **Privacy first:** Think about sensitive data from the start.
- **Keep it simple:** Build small tools that do one thing well.
- **Be explicit:** Document security assumptions and limitations.
- **Test the hard parts:** Include edge cases and adversarial tests.
- **Build in the open:** Share the code, decisions, and lessons learned.

## Security reviews and contributions

Security reviews are welcome. We'd love more eyes on the code.

If you're into application security, cryptography, or privacy engineering, take a look at the projects and challenge the design or implementation.

Some areas worth exploring:

- Threat modelling and architecture.
- Cryptography and key management.
- Sensitive-data handling and deletion.
- Access control and vulnerability testing.

Bug reports, security findings, feedback, and pull requests are all welcome.

Found a potential vulnerability? Please report it privately using the instructions in the relevant repository's `SECURITY.md`.
